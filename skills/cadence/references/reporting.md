# Review reporting

Use this reference when assembling curriculum-review findings.

## Default presentation

Lead with the decision-useful result, not the audit trail. The default concise review contains:

1. A two- or three-sentence overall judgment.
2. No more than five primary findings, ordered by consequence.
3. For each finding: the gap, why it matters, and the recommended action.
4. Up to three established strengths.
5. A short limitations statement and the next decision.

Prefer a compact table when findings repeat the same fields:

| Priority | Finding | Why it matters | Recommended action |
| --- | --- | --- | --- |

Do not put source inventories, long rationales, or passage identifiers in the executive review. Link the detailed audit instead.

## Length defaults

- Progress update: one or two sentences.
- Clarifying question: one short paragraph.
- Formal-audit phase checkpoint: at most 150 words in chat.
- Executive review: usually 600–1,000 words; shorter when the evidence supports it.
- Primary findings: normally three to five.
- Detailed evidence audit: as long as needed for accuracy, traceability, and institutional review.

These are defaults, not reasons to omit a critical qualification or a user-requested detail.

## Findings discipline

- Consolidate repeated manifestations of one root problem into a single finding.
- Distinguish curriculum defects from missing review evidence.
- Keep severity labels few and stable: critical, high, moderate, minor.
- Do not promote a minor typo into a primary finding.
- Put citations, source authority notes, coverage, accepted limitations, and minor inaccuracies in the detailed audit.

## Editable Word audit with comments

When the user requests a Word audit, create a `.docx` version of the detailed audit and add true Word comments anchored to the exact finding heading or sentence that needs attention.

- Read and apply [docx-formatting.md](docx-formatting.md) before building the document. An applicable institutional template or explicit user direction takes precedence; otherwise use the established Cadence baseline.
- Each comment should state the practical problem and the decision or correction needed.
- Use one comment per distinct actionable issue; avoid commenting every citation or repeating the report body.
- Anchor each comment range to the narrowest meaningful wording in the substantive section that creates the issue. Do not attach comments only to a general limitations list, gap-summary bullet, endnote, or separate comment table when the affected passage exists elsewhere.
- Verify the highlighted range itself, not only that the comment appears in the comments collection.
- Preserve evidence citations as readable text in the document.
- Use the available document-authoring workflow to render and inspect every page.
- Verify comments structurally: `word/comments.xml`, document anchors, the comments relationship, and the content-type override must all be present. A clean PDF render does not prove comments exist.
- Deliver the executive review first, then the commented Word audit and optional Markdown evidence report.

## Formal audit mode

Formal audit mode retains phase reports, evidence citations, coverage notes, source/version authority, decisions, and approval gates. Even in formal mode, keep conversational summaries short and make the detailed report the place for audit depth.
